# Review implementation and QA — 2026-09-16

This pass implements the twelve review items without changing the classic-script architecture, balance tables, mission count, or flat terrain.

## Delivered changes

- Mission transitions clear projectiles/effects before spawning the next battlefield, and remove old building occupancy before generating new terrain.
- Failed AI building placement preserves credits.
- Harvesters choose completed friendly refineries and cancel an unload if the refinery is destroyed or captured.
- Radar readiness requires a completed, powered facility in the HUD, minimap, fog update, and airstrike execution.
- Build cards explain missing prerequisites, cost, time, power, and insufficient funds; keyboard focus/activation and virtual-cursor hover are supported.
- HUD construction metadata comes from the shipped specs and TechTree requirements.
- Biome textures now have deterministic ground routes and clearings. HQ and infantry materials provide clearer structure and faction markings.
- Weapon impacts use reusable procedural sprite assets and fading ground marks.
- Owned geometry, materials, and textures are released on effect expiry, entity removal, terrain regeneration, building capture, and placement-preview cleanup. Shared projectile assets survive mission resets.
- Unit separation preserves logical collision order but synchronizes each moved mesh once per pass.

## Verification

The browser QA covered all three mission biomes, mission transitions, keyboard construction, locked-card tooltip focus, live harvesting, radar construction/power states, and the real weapon-effects harness at `/tests/visual_effects.html` through the local HTTP server. The harness exposes pause/slow controls and GPU counters for repeatable visual checks.

After firing all weapon types and clearing twice, the VFX harness returned to 0 active effects, 7 cached geometries, and 1 cached texture each time, with no browser console errors. The cached assets are deliberately retained for reuse.

## Proximity benchmark

`tests/benchmark_entities.js` uses real shipped infantry. It reports medians of five samples, with 100 iterations per sample after warmup. The crowded case resets a dense moving formation each iteration; its time includes the reset. Targeting deliberately queries every unit each iteration. Rendering, pathfinding, and AI are not included.

| Units | Crowded separation before (ms) | After (ms) | Dispersed separation after (ms) | All-unit targeting after (ms) |
| --- | ---: | ---: | ---: | ---: |
| 32 | 0.340 | 0.236 | 0.025 | 0.015 |
| 96 | 2.469 | 0.453 | 0.060 | 0.149 |
| 192 | 5.613 | 1.614 | 0.224 | 0.245 |

These are local CPU measurements, not an FPS guarantee; timings vary with machine load. They justify batching mesh updates, while the dispersed/target-search measurements do not yet justify a spatial-index rewrite. The existing human balance ladder in `balance-testing.md` remains separate from this regression and visual pass.

Final automated checks: 45 simulation tests, script-load/input/radar regressions, resource lifecycle checks, and diff whitespace checks passed. The rejected-command sound cue is also defined, avoiding an exception when a locked or unavailable action is attempted.
